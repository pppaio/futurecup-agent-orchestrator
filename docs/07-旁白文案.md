# 演示视频旁白文案（最终稿）

> 语速约 230 字/分钟，全文约 1000 字 ≈ 4 分半。对应 docs/06-视频分镜.md 的 8 个镜头。
> 括号内【】为待填实验数字。

---

**镜1 开场（0:00–0:25）**

现在你让 AI 写个小游戏，它经常给你一段"看着对、一跑就崩"的代码，最后还得你自己去人工核验。我们做了一个多智能体编排平台，把"能不能跑"这件事，交给机器来判定。

**镜2 任务台（0:25–0:55）**

这是任务台。我只输入一句话——"做个能玩的打砖块"——点开始生成。剩下的事交给平台：分析师先把需求拆成一条条可机械验收的条件。

**镜3 运行看板·编排（0:55–1:50）**

这是实时运行看板。左边是七个节点，分析师、生成者、硬验证、软裁判……每一步亮一个；中间是实时事件流，每个 Agent 在干什么、说了什么，全程可见。生成者产出单文件 HTML 之后，会被丢进一个无头浏览器里真跑一遍。

**镜4 修复闭环（1:50–2:30）**

注意看，这一版跑挂了——报错就是报错，Agent 没法自我说服。系统把报错压成不超过三张错误卡片，回灌给修复者重写，最多三轮。看这条错误曲线，从 1 降到 0，收敛了。

**镜5 中断插入（2:30–3:10）**

更关键的是：跑的过程中你觉得方向不对，可以随时点中断，加一句"加个计分板"，再从断点继续。用户中途接管 Agent，这是行业公认的开放问题，我们给出了一个能跑的实现。

**镜6 核验报告（3:10–3:50）**

最终交付的不是"一段代码"，而是一份带核验报告的可运行产物。硬验证通过、软裁判打分、错误曲线可查、产物一键下载，整个过程可复现。

**镜7 数据（3:50–4:30）**

在 20 条需求的测试里，一次可运行率从单 Agent 基线的【__%】提升到【__%】。三组对比证明了同一件事：多 Agent 本身不值钱，值钱的是验证角色和执行角色的对抗。

**镜8 收尾（4:30–5:00）**

别人让 AI 说它对，我们让机器证明它对。谢谢观看，欢迎提问。
