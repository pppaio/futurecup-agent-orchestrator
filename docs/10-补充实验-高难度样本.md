# 补充实验：高难度样本组

> 目的：修复一个致命软肋——现有 20 条样本首轮可运行率 **95%**、收敛轮次**中位数 0**，导致「自我循环」这条核心卖点在数据上几乎不存在（20 次只触发 1 次）。
> 做法：**新增 2 条难样本，单独跑 S1/S2/S3，不改动原 20 条结果**，作为"补充实验"报告。
> 预算：约 40~120 分钟算力时间、¥5~15。**后台跑，人不用盯。**

---

## 1. 选样原则（关键，别自己加样本）

沙箱只能捕获三类失败：`console.error` / `pageerror` / 白屏（canvas 空）。

**它捕获不到"逻辑错了但代码没崩"。** 所以难样本必须满足两条：

1. **失败必须响亮**：错了就抛异常或白屏，不能静默地"看起来对但不对"。
2. **必须在 3 轮内可修好**：修不好的样本会连带把 S3 也拉下水，反而自伤。

按此标准淘汰的候选：

| 候选 | 淘汰原因 |
|---|---|
| 塔防（寻路/波次/经济） | 难度过高，3 轮修复大概率不收敛 → S3 也失败 |
| 粒子/矩阵雨 + 帧率 | 纯视觉，首轮就过，等于白跑 |
| 排序演示器 + 撤销 | **最危险**：撤销错误不抛异常，沙箱判 `ok=true`，S1 也"通过" → 得到"我们和基线一样"的反向结论 |

## 2. 两条样本（文案已定稿，不要改字）

要求：与原 20 条风格一致（一句话、不列清单），但隐含多重约束。

```ts
// H1：多实体 + 帧循环 + 关卡状态机（失败最响亮：数组越界/null 属性必抛错）
{ id: 'h1', category: '高难度·多实体',
  requirement: '做一个太空弹幕射击：3 种敌人（直线下压、左右横移、追踪玩家）各自发射不同弹幕，玩家 3 点血量，被击中扣血，击毁 20 个敌人进下一关，每关敌人生成速度与弹幕密度递增' }

// H2：物理 + 边界 + 关卡状态（失败常表现为白屏或物理量失控）
{ id: 'h2', category: '高难度·物理状态',
  requirement: '做一个平台跳跃：重力和平台碰撞、可二段跳、会左右移动的陷阱、碰到陷阱血量归零重开本关、集齐全部金币通关、方向键移动、空格跳跃' }
```

**为什么是这两条**：
- H1 有最多可变状态（敌人 × 弹幕 × 血量 × 关卡），最容易出运行时异常；
- H2 是物理 + 关卡状态，典型失败是"能加载但角色穿墙/掉出画面"，会体现为 canvas 异常或物理量失控；
- 两条覆盖**两类**失败：`多实体状态` vs `物理与边界`。这样结论可以说"覆盖两类失败模式"，而不是单点轶事。

> 跑完记得 `Remove-Item Env:COMPARE_SET` 之类的清理，避免影响后续正常 compare。

### 三个预警

| 风险 | 表现 | 处置 |
|---|---|---|
| **单 run 超时** | 引擎 `timeout_sec` 默认 900s，难样本 S3 带 3 轮修复可能撞上限 | 若日志出现 timeout，把 `GAME_GEN_WF.limits.timeout_sec` 临时调到 1800 |
| **余额不足** | README 记录余额 ¥32.25 | 难样本 token 约为简单样本 2~3 倍，预计 ¥5~15，够；不足先充 |
| **S3 也不收敛** | 6 个 run 里 S3 有失败 | **不要删数据**。这正是"带缺陷交付"机制该出场的地方，如实记录反而能证明机制诚实 |

## 5. 结果怎么用（两种走向，都有话说）

3. PPT 加一页，标题就用「**难任务上，循环才真正开始工作**」。

### 走向 B：S1 也全通（也是有效结论，别慌）

说明当前模型已越过这个难度线。此时**不要硬吹循环**，改措辞：

> 在 n=2 的高难度样本上，基线方案也已能一次通过——这说明该任务域的生成能力已较强。我们的差异化不在"提高成功率"，而在**把不确定性关进笼子**：失败可解释、过程可复现、方向可干预、轮次有上限。

对应动作：把方案书 §4.2 的标题从「自我循环机制（灵魂模块）」改为「**自我循环机制（保险丝）**」，并把局限章节的"循环触发率 1/20"如实保留。

> 评分细则里「有误差、局限的讨论」是加分项。**主动交代比被问穿强。**
