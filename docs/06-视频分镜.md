# 演示视频分镜（3~5 分钟）

> 赛题要求：完整展示 平台界面 / Agent 编排过程 / 任务调度执行 / 结果验证 / 反馈循环。
> 三个镜头对应前端三页。录屏 + 旁白。

---

## 总时间轴

| 时间 | 镜头 | 内容 |
|---|---|---|
| 0:00–0:25 | 开场 | 痛点 + 一句话主张 |
| 0:25–0:55 | 任务台 | 输入"做个能玩的打砖块"→ 开始 |
| 0:55–1:50 | 运行看板 | 节点依次点亮 + 事件流滚动（分析→生成→硬验证） |
| 1:50–2:30 | 看板·修复 | 验证失败 → 错误卡片 → 修复者 → 再验证通过（error_curve 下降） |
| 2:30–3:10 | 看板·中断 | 点中断 → 输入"加个计分板" → 续跑 → 新版含计分板 |
| 3:10–3:50 | 核验报告 | 收敛曲线 + 硬验证明细 + 软评分 + 下载产物 |
| 3:50–4:30 | 数据 | 可运行率 + 三策略对比（一句结论） |
| 4:30–5:00 | 收尾 | 一句话记忆点 + 致谢 |

## 分镜脚本

### 镜1 · 开场（0:00–0:25）
- 画面：黑底标题「能不能跑，机器说了算」
- 旁白：现在让 AI 写个小游戏，它经常给你一段"看着对、一跑就崩"的代码，你还得人工核验。我们做了一个多智能体编排平台，把"能不能跑"交给机器判定。

### 镜2 · 任务台（0:25–0:55）
- 画面：任务台输入框，输入「做个能玩的打砖块」，点「开始生成」
- 旁白：一句话需求进去，剩下交给平台。分析师先把它拆成可机械验收的条件。

### 镜3 · 运行看板 · 编排执行（0:55–1:50）
- 画面：看板左侧节点依次点亮：n1 分析师 → n2 生成者 → n3 硬验证；中间事件流滚动
- 旁白：这是实时看板，每个 Agent 在干什么、说了什么，全程可见。生成者产出单文件 HTML 后，交给无头浏览器真跑一遍。

### 镜4 · 修复闭环（1:50–2:30）
- 画面：硬验证报错（红色）→ 错误卡片 → n5 修复者 → 再验证通过（绿色）→ 打包
- 旁白：报错就是报错，Agent 没法自我说服。失败会被压成不超过三张错误卡片，回灌给修复者重写，最多三轮。看这条错误数曲线，从 1 降到 0。

### 镜5 · 中断插入（2:30–3:10）
- 画面：点「中断」→ 状态变 paused → 输入「加个计分板」→ 点「续跑」→ 产物预览更新
- 旁白：跑的过程中你觉得方向不对，可以随时掐断、加一句要求、从断点继续。这是行业公认的开放问题，我们给出了能跑的实现。

### 镜6 · 核验报告（3:10–3:50）
- 画面：报告页收敛曲线条形图 + 硬验证明细（0 错误）+ 软评分 + 下载按钮
- 旁白：最终交付的不是"一段代码"，而是一份带核验报告的可运行产物：机器判定通过、软裁判打分、错误曲线可查、可复现。

### 镜7 · 数据（3:50–4:30）
- 画面：可运行率数字 + 三策略对比表
- 旁白：在 20 条需求的测试里，一次可运行率从 __% 提升到 __%。三组对比证明：多 Agent 本身不值钱，值钱的是验证角色和执行角色的对抗。

### 镜8 · 收尾（4:30–5:00）
- 画面：黑底「别人让 AI 说它对，我们让机器证明它对。」+ 队名
- 旁白：谢谢观看，欢迎提问。
