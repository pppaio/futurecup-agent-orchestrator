# 验收测试需求与预期（跑之前开录屏）

> 用途：① 验证平台在难任务上的真实表现 ② 顺手产出演示视频素材 ③ 可作为 hard 实验的手工补充
> 判定总则：**所有「硬预期」全过 = 达成**；任一条不过 = 未达成，记录错误卡片与轮次。

---

## R1 · 环形贪吃蛇（难度：中 · 预计 2~4 分钟 · 首轮 0~2 错，1 轮内收敛）

**需求文案（直接粘贴）**

```
做一个贪吃蛇：地图左右上下都是环形的（从右边穿出会从左边进入），吃到食物身体变长，每吃 5 个食物移动速度加快一次，界面上显示当前分数和速度等级
```

**预期（勾选表）**

| # | 类型 | 预期 | 达成 |
|---|---|---|---|
| 1 | 硬 | 页面加载 0 条 console 错误，画布非空 | ☐ |
| 2 | 硬 | 蛇从右边界穿出后**从左侧进入并继续存活**，不判死 | ☐ |
| 3 | 硬 | 上下穿越同样成立 | ☐ |
| 4 | 硬 | 吃到食物后身体长度 +1，分数 +1 | ☐ |
| 5 | 软 | 每 5 个食物后速度等级 +1，且加速可见但不失控 | ☐ |
| 6 | 软 | 撞到自己身体时游戏结束并可重开 | ☐ |

**最可能崩的点（重点看这几处）**
- 穿墙用 `if` 判断而非取模 → 从右穿出时直接判死，或蛇瞬移到左上角。
- 加速时重复 `setInterval` 未清理旧定时器 → 速度指数级飙升，玩几秒就不可控。
- 环形之后自撞判定没排除"头尾相接" → 一出生就死。

**判读**：第 2 条是这条的命门。穿墙即死 = 未达成。

---

## R2 · 双人同屏坦克对战（难度：高 · 预计 3~6 分钟 · 首轮 1~4 错，1~2 轮收敛）

**需求文案**

```
做一个双人同屏对战坦克：P1 用 WASD 移动、空格开火，P2 用方向键移动、回车开火，子弹撞到墙壁会反弹一次（第二次撞墙消失），地图中央有可被击毁的砖块，一方被击中三次即负，结束后显示胜方并可按键重开
```

**预期（勾选表）**

| # | 类型 | 预期 | 达成 |
|---|---|---|---|
| 1 | 硬 | 加载 0 错误，画布非空 | ☐ |
| 2 | 硬 | **两辆车可同时移动且互不干扰**（同时按 WASD 与方向键，各自方向正确） | ☐ |
| 3 | 硬 | 子弹撞墙后方向反转并继续飞行；同一颗子弹第二次撞墙消失 | ☐ |
| 4 | 硬 | 子弹击中砖块后砖块消失 | ☐ |
| 5 | 硬 | 一方累计被击中 3 次 → 显示胜方 | ☐ |
| 6 | 硬 | **按重开键后场上无残留子弹/无残留砖块状态**，可正常再战一局 | ☐ |
| 7 | 软 | 坦克有朝向，子弹沿朝向发射 | ☐ |

**最可能崩的点**
- **键盘状态共用一个变量** → 两玩家移动互相串（第 2 条最常见的失败）。
- 子弹没记 `bounceCount` → 无限反弹不消失，几十颗子弹后卡成幻灯片。
- 重开只重置分数没清实体数组 → 一按重开满屏旧子弹（第 6 条）。
- 砖块用二维数组但索引写成 `[y][x]`/`[x][y]` 混用 → 击毁位置错乱。

**判读**：第 2 条和第 6 条是这条的两个命门。这条**最适合做视频的"修复闭环"镜头**——失败信号很明确（画面卡死或双人互串）。

---

## R3 · 俄罗斯方块 + 幽灵预览 + AI 自动落子（难度：很高 · 预计 5~10 分钟 · 可能 2~3 轮或带缺陷交付）

**需求文案**

```
做一个俄罗斯方块：7 种方块随机出现、界面显示下一个方块、有幽灵方块预览落点、按 P 键让 AI 自动选择当前最佳落点并落子、消行得分、方块堆到顶部则游戏结束
```

**预期（勾选表）**

| # | 类型 | 预期 | 达成 |
|---|---|---|---|
| 1 | 硬 | 加载 0 错误，画布非空 | ☐ |
| 2 | 硬 | 7 种方块都能出现，旋转后形态正确 | ☐ |
| 3 | 硬 | 幽灵块位置 = 当前方块**直落到底**的位置，且**不改变当前方块本身** | ☐ |
| 4 | 硬 | 按 P 后方块自动移动到 AI 选定列并落子锁定 | ☐ |
| 5 | 软 | AI 连续落子 20 次不卡死、不出现方块重叠 | ☐ |
| 6 | 软 | 消行正确（整行消除、上方下移、得分按行数递增） | ☐ |

**最可能崩的点**
- 幽灵块复用了当前方块**对象引用** → 一画幽灵，方块本体消失或与幽灵重叠。
- 旋转不做边界/墙踢 → 方块贴边时卡死不动。
- AI 评估函数列高算错 → 堆到顶上，游戏提前结束。
- 消行后未重排矩阵 → 出现"空气行"。

**判读**：这条如果失败，**别删**——它正好演示平台的「带缺陷交付 + 缺陷报告」，对"错误恢复"这个评分点是正面证据。

---

## 执行顺序与记录

1. **R1**（稳）→ 2. **R2**（中高，重点录屏）→ 3. **R3**（很高，时间够才跑）
2. 任务台里把**循环轮次上限设为 3**、思考强度 medium 或 high，避免跑飞。
3. 每条跑完记录一行：

```
编号 | 是否一次通过 | 修复轮次 | 未通过的硬预期编号 | 平台是否给出缺陷报告 | 耗时
R1   |              |          |                     |                       |
R2   |              |          |                     |                       |
R3   |              |          |                     |                       |
```

### 结果怎么解读

| 结果 | 含义 | 动作 |
|---|---|---|
| R1/R2 一次通过 | 平台在当前难度下稳定，但"修复闭环"缺素材 | 视频里用 `demo:workflow` 的受控注入演示修复 |
| R2 出现 1~2 轮修复 | **最理想**：真实失败 + 真实修复 | 这段录屏直接进视频 |
| R3 带缺陷交付 | 机制诚实运作 | 把缺陷报告截图进 PPT，作为"错误恢复"证据 |
| 三条全一次过 | 难度不够 | 才需要加更难样本，否则别加 |

---

## 一条提醒

**先把这三条跑完再谈加难度。** 现在最缺的不是更难的游戏，是"有失败、有修复、有曲线"的证据。跑出来的一手数据，比任何设计都值钱。
