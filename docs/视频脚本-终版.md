# 项目介绍视频脚本（3~5 分钟 · 终版）

> 赛题硬性要求：**必须完整展示五个环节** —— 平台界面 / Agent 编排过程 / 任务调度执行 / 结果验证 / 反馈循环。
> 目标时长 **4:00**。语速约 230 字/分钟，旁白总量约 900 字。
> 不要配 BGM。讲解听不清会直接扣分。

---

## 录制准备（15 分钟）

1. `cd agent-platform` → `npm run serve` → 浏览器开 `http://localhost:3000`
2. **窗口固定 1600×900**，浏览器缩放到 100%，隐藏书签栏（F11 全屏更好）
3. OBS 录**整个屏幕**（不要只录浏览器，后面要切到终端/报告）
4. 关掉微信、QQ、任何会弹窗的东西
5. **先空跑一遍**，确认要跑的需求能出结果，再正式开始录
6. 分辨率 1080p，帧率 30 即可

**拍摄顺序建议**：先录最难的镜 4-5（失败与修复），再录稳的镜 2-3。失败镜头最难复现，先把它拿到手。

### 镜 2 · 任务台：一句话需求（0:20–0:50）

| 项 | 内容 |
|---|---|
| 操作 | 打开任务台 → 在输入框粘需求 → 点"开始" |
| 画面 | 需求输入框、角色组下拉、开始按钮 |
| 对应要求 | **平台界面** |

**粘贴的需求（R2）**
```
做一个双人同屏对战坦克：P1 用 WASD 移动、空格开火，P2 用方向键移动、回车开火，
子弹撞到墙壁会反弹一次（第二次撞墙消失），地图中央有可被击毁的砖块，
一方被击中三次即负，结束后显示胜方并可按键重开
```

**旁白**
> 我输入一句话需求：做一个双人同屏对战的坦克游戏。
> 注意这不是一个表单，只有一句话——平台要自己把它拆成可验收的条件。

### 镜 3 · 运行看板：编排过程（0:50–1:40）

| 项 | 内容 |
|---|---|
| 操作 | 停在看板，让节点依次点亮；滚动事件流；**点开一个气泡**看 thinking |
| 画面 | 节点图状态变色、事件流滚动、气泡、右侧产物预览 |
| 对应要求 | **Agent 编排过程 + 任务调度执行** |

**旁白**
> 这是运行看板。左边是工作流节点，正在按依赖关系依次点亮——分析师拆解需求，生成者写代码，然后硬验证和软裁判并行跑。
>
> 中间这条是事件流，每个 Agent 在想什么、调了什么工具，都是实时的。
>
> 点开这条气泡，可以看到分析师的原始思考：它把"子弹撞墙反弹一次"翻译成了一条**可被程序判定的验收条件**——第二次撞墙必须消失。
>
> 这一步很关键：如果验收条件写成"游戏要好玩"，后面就没法机械验证了。

---

### 镜 4 · 结果验证：跑挂了（1:40–2:20）

| 项 | 内容 |
|---|---|
| 操作 | 停在硬验证失败的节点，放大错误卡片与报错截图 |
| 画面 | `ok=false`、错误条数、错误分类卡片、行号、截图 |
| 对应要求 | **结果验证** |

**旁白**
> 到这里，生成者交出的第一版被硬验证拦住了。
>
> 这个环节**不是大模型在判断**，是一个无头浏览器真的把产物加载了一遍，抓到了控制台报错。所以这个"不通过"是事实，不是评价——Agent 没法靠解释拿到通过。
>
> 平台把 7 条报错压成了 3 张错误卡片，每张带分类、行号和截图。**压缩用的是确定性代码，不是模型**——如果让模型去归约错误，噪声会被放大成新的错误。

---

### 镜 5 · 反馈循环：回灌修复（2:20–2:50）

| 项 | 内容 |
|---|---|
| 操作 | 切到下一轮：修复者产出新版本 → 再验证 → 错误数下降 → `ok=true` |
| 画面 | 轮次 +1、错误数 3→1→0、收敛曲线出现 |
| 对应要求 | **反馈循环** |

**旁白**
> 修复者只收到错误卡片和需求摘要，看不到整份代码——这是为了控制上下文，也是防止它在全局上瞎改。
>
> 第二轮、第三轮，错误数在往下走。右下角这条就是收敛曲线。
>
> 我们给循环装了四道闸：轮次上限 3、调用指纹去重、错误数连续两轮不降就升级、超限就**带缺陷交付**。而且判断这些的是一个循环之外的观察者，只看硬信号——所以我们敢说它一定会停。

---

### 镜 6 · 关键操作：中断、插入、续跑（2:50–3:20）

| 项 | 内容 |
|---|---|
| 操作 | 点"中断" → 弹窗输入"让坦克移动速度更快一些" → 点"续跑" |
| 画面 | 状态变 paused、输入框、恢复后节点继续、新版本体现改动 |
| 对应要求 | **关键操作（人机协作）** |

**旁白**
> 现在演示我们认为最有价值的一个能力。跑到一半，我点中断。
>
> 注意是**立刻**停下的，不用等当前那次模型调用返回——因为所有长耗时调用都是异步两段式，在途结果会被丢弃。
>
> 我插入一句"让坦克移动更快"，然后续跑。已完成的节点不会重跑，只从断点继续。
>
> 用户中途接管 Agent，业界目前还没有通用解法。我们在"产物可验收"这个窄域里，给出了一个能跑的答案。

## 剪辑要点

| 项 | 说明 |
|---|---|
| 加速 | 等待模型返回的空白时间用 **4~8 倍速**，不要静音跳过（观众要看到它在跑） |
| 标注 | 在第一轮失败处加一个大字标注「第 1 轮 ✗ 3 条错误」，第二轮「✓ 0 条」 |
| 不要 | 不要加背景音乐；不要加花哨转场；不要出现 API Key、余额、真实姓名 |
| 字幕 | 关键术语加字幕：硬验证、错误卡片、收敛曲线、Self-Loop |
| 时长 | 超过 5:00 必须剪，短于 3:00 会被认为不完整 |

## 三条兜底

1. **失败镜头拍不到**：改用 `npm run demo:workflow`（受控注入错误），**旁白必须明说"这里用受控注入的方式演示修复闭环"**。别冒充真实生成。
2. **真模型太慢**：镜 2/3/7 用真模型，镜 4/5 用 fake 模式，分两次录再拼。
3. **时间不够**：砍镜 7 的试玩，砍镜 8 的收口，但**镜 4 和镜 5 绝不能砍**——那是评分表里"结果验证与反馈循环"的直接证据。
