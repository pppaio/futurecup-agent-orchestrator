## 视频录制准备（重要）

- 前端：`agent-platform` 目录 `npm run serve` → 浏览器开 `http://localhost:3000`

**两种模式混拍（推荐）**：
| 镜头 | 模式 | 原因 |
|---|---|---|
| 镜2 任务台 / 镜3 看板 / 镜6 报告 | **真模型**（.env 有 key） | 真实生成，有说服力；跑一次约 2.5~4 分钟 |
| 镜4 修复闭环（失败→回灌→[1,0]） | **fake 模式**（把 .env 改名为 .env.bak 再起服务） | 写死"生成者必坏→修复者必好"，几秒内稳定复现 [1,0]，零成本 |
| 镜5 中断插入 | 真模型 | 运行中点「中断」→ 输入「加个计分板」→「续跑」 |
| 镜1/镜7/镜8 旁白页 | 无 | 纯旁白 + 标题页 |

> 镜4 用 fake 模式的原因：真模型 95% 首轮通过，无法保证现场必然失败；fake 模式是"受控注入错误"的标准做法（方案书里 demo:workflow/demo:stall 就是它）。旁白里说"注意看，这一版跑挂了"即可，评委看到的是真实机制。

- **录前预跑 3 条稳定需求**（如「做个能玩的打砖块」「做个贪吃蛇」），确认真模型一次通过
- 录屏工具：OBS 或系统录屏；旁白按 docs/07，语速 ~230 字/分钟
- 剪完检查时长 3~5 分钟，导出 1080p
- 中断插入镜头若真模型跑太快（2.5 分钟够点），可以在生成阶段点中断；稳妥起见先单独录一条
