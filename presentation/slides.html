问题

AI 生成的代码，「看着对、一跑就崩」

① 生成 ≠ 可用

大模型擅长"看起来像"，不擅长"真的能跑"；产物可靠性靠人肉核验，成本高、不可复现。

② 幻觉会传播

多 Agent 协作中，上游的错误输出被下游当事实使用，没有关卡拦截，越传越偏。

③ 循环没有闸

"再改一次"式的自我循环缺乏收敛判据，常见结果是无休止的伪修复与无限重试。

→ 我们的回答：把验收从"模型自述"换成机器判定，把循环从"无限重试"换成四道闸。
2 / 15
核心主张
能不能跑，机器说了算
验收是二值事实：页面能否加载、控制台有无报错、画面是否渲染、交互是否抛错——全部由无头浏览器实测判定，不可争辩、可复现。
LLM 只被允许做两件事：生成，和评价好不好用。它不负责判定能不能跑。

系统总览

一句话需求 → 确定可运行的软件产物

一句话需求→ 分析师拆解→ 生成者产出→ 无头浏览器硬验证⇄ 失败回灌修复 ≤3轮→ 打包交付 + 核验报告

产物形态确定

单文件 HTML/JS，无后端、无构建。运行环境完全确定 → 错误可 100% 捕获回灌。

全过程可观测

append-only 事件流实时推送：每个 Agent 干了什么、说了什么，随时可见、可中断、可回放。

架构

三层 + 一份存储

层职责
前端（三页）任务台 / 运行看板 / 核验报告 —— 演示视频的全部镜头
编排引擎 Core纯逻辑可单测：解析器 → 调度器 → 执行器 → 验证门控 → Self-Loop 控制器 → 人工介入控制器 + 外部观察者 Loop Watchdog
可插拔能力层LLM Gateway / 沙箱(Playwright) / 工具层 / RAG / 打包器 —— 全部依赖注入，可 fake 先行

多 Agent

五个角色，一条带闭环的 DAG

角色职责判定权
分析师 analyst需求 → 可机械验收的规格 + 假设 + 歧义—
生成者 builder规格 → 单文件 HTML 产物—
硬验证沙箱 hard-sandbox无头浏览器实测：加载/报错/渲染/交互能否运行（阻断）
软裁判 critic对照验收条件打分 1-5 + 偏差好不好（不阻断）
修复者 fixer错误卡片 + 摘要 → 新版产物—
关键：验证角色与执行角色是对抗关系——这就是"多 Agent"值钱的地方，而不是 Agent 数量。
7 / 15
验证

硬验证：Playwright 无头浏览器

判定规则（写死，不含 LLM）

ok = 页面加载成功
    && 控制台/页面错误 = 0
    && (图形类: canvas 非空 | 工具类: DOM 有内容)
    && 交互脚本不抛错

为什么它可信

加载、报错、渲染、交互都是实测的二值信号；失败即回灌，Agent 无法自我说服；判定结果可复现、可审计。图形类/工具类由分析师在规格里声明（graphic 字段）。

主动写明局限：L1 只能证明"能跑"，不能证明"好玩/完成度高"——后者交给软裁判与人评。
8 / 15
灵魂

自我循环 + 外部看门狗

生成/修复→ 硬验证⇄ 错误归一化 ≤3卡片→ 回灌修复者

四道闸（全部落码，外部观察者判定）

闸判据动作
轮次上限修复循环 ≤ 3 轮超限带缺陷交付，绝不假装成功
无进展升级错误数连续 2 轮不降escalate：拆更细 / 提档 / 转人工
根因未命中错误卡片集合重复出现escalate：附"已尝试过的修法"
假进展中止修复者输出与上轮完全相同abort：防御性妥协当场抓包
Loop Watchdog 是外部只读观察者：只看硬信号，不看 Agent 自述——这就是"自我循环"和"无限重试"的本质区别。
9 / 15
原则

两级判定：Fast Path / Slow Path

层级谁判定判定什么阻断？
L1 硬验证沙箱脚本（非 LLM）能否加载、有无报错、渲染/交互是，失败即回灌
L2 软验证LLM 裁判验收条件满足度、可玩性 1-5否，低于阈值才提示
L3 人工用户最终验收 / 中断干预是

一句话原则

能写成 if 的判断，绝不交给模型。确定性代码是快路径——便宜、可复现、零幻觉；LLM 只在语义问题上走慢路径。这同时解释了我们的成本优势：大部分判定不烧 token。

10 / 15
差异化

可中断 · 可插入 · 可复现

人工介入节点

运行中随时中断 → 暂停（在途节点跑完即停）→ 插入指令（"加个计分板"）→ 断点续跑。指令作为高优先级消息注入下一 Agent 上下文，并记入事件流。用户中途接管 Agent 是行业公认的开放问题，我们给出了能跑的实现。

可复现三件套

每次运行落盘 run.json（模型快照 + seed + 产物 sha256）+ events.jsonl。事件流可完整重放一次运行；暂停快照 = 事件流末尾位置，不另建状态表。

诚实声明

我们主动写进文档的局限

  • L1 只证明"能跑"，不证明"好玩"；对图形类依赖 canvas 非空这类弱信号。
  • 样本 20 条、单模型单次采样，结论不可外推到任意软件生成。
  • Analyst 拆解错误会向后传导——歧义停机是缓解手段，无法根除。
  • 多 Agent 的每一跳都是一次 LLM 往返，简单任务上耗时高于单 Agent；我们不以"更快"为卖点，卖点是"一次通过率"。
  • 人评由作者完成，存在主观偏差。
主动写局限 = 评分细则里"误差、局限讨论"那一项的分。
